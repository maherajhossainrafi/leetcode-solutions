# Documentation of Concatenation of Array

## 1. Problem Title

**Concatenation of Array** (LeetCode 1929, C++) · [Problem link](https://leetcode.com/problems/concatenation-of-array/)

## 2. Problem Summary

You are given an integer array `nums` of length `n`. Build `ans` of length `2n` where, for every `i` from `0` to `n - 1`:

- `ans[i] == nums[i]` (first half)
- `ans[i + n] == nums[i]` (second half)

In short: `nums` written twice, end to end. Example: `[1, 3, 2, 1]` becomes `[1, 3, 2, 1, 1, 3, 2, 1]`. LeetCode guarantees `1 <= n <= 1000`.

## 3. Intuition

Picture a row of `n` tiles that must be laid out twice in a row. Positions (indexes) start at `0`. The second copy begins `n` slots after the first, so the value at position `i` belongs in two places: `i` and `i + n`.

That means one loop of `n` rounds, with two writes per round:

| `i` | writes | `ans` afterward |
|-----|--------|-----------------|
| start | | `[0,0,0,0,0,0,0,0]` |
| 0 | `ans[0]`, `ans[4]` = 1 | `[1,0,0,0,1,0,0,0]` |
| 1 | `ans[1]`, `ans[5]` = 3 | `[1,3,0,0,1,3,0,0]` |
| 2 | `ans[2]`, `ans[6]` = 2 | `[1,3,2,0,1,3,2,0]` |
| 3 | `ans[3]`, `ans[7]` = 1 | `[1,3,2,1,1,3,2,1]` |

## 4. Approaches

1. **Sized vector:** create `ans` with `2n` zero-filled slots, then fill two slots per round (calling `nums.size()` each time).
2. **Growing vector:** start with an empty `ans` and `push_back` every value of `nums`, twice (two loops).
3. **Stored length:** the same as approach 1, but store `n = nums.size()` once in an `int`.

## 5. Complexity Analysis

| Approach | Time | Space (total, with answer) | Extra space (without answer) |
|----------|------|----------------------------|------------------------------|
| 1. Sized vector | `O(n)` | `O(n)` | `O(1)` |
| 2. Growing vector | `O(n)` | `O(n)` | `O(1)` plus temporary buffers while growing |
| 3. Stored length | `O(n)` | `O(n)` | `O(1)` |

- **Why `O(n)`:** a loop of `n` rounds doing constant work per round. Constants are dropped in Big-O.
- **Hidden cost:** `vector<int> ans(2 * n)` zero-fills `2n` slots (about `2n` steps).
- **Amortized `O(1)` push_back:** when a vector is full it allocates about double the room and copies the old values. Those copies add up to less than twice the number of pushes, so the average cost per push is constant.
- **No solution can beat `O(n)`:** the output itself has `2n` values. Only constants and clarity differ.
- Always state both space numbers: *`O(n)` counting the output, `O(1)` extra excluding it.*

## 6. Edge Cases

- `[5]` gives `[5, 5]`: `n = 1`, one loop round, two writes.
- `[4, 4]` gives `[4, 4, 4, 4]`: copying is by position, not by value.
- `n = 1000`: the highest index written is `999 + 1000 = 1999`, inside 2000 slots.
- Empty `nums` (outside the constraint) gives an empty `ans`, because the loops run zero times.
- Every slot of `ans` is written exactly once, with no gaps or overlaps.

## 7. Implementations

**Approach 3 (recommended):**

```cpp
vector<int> getConcatenation(vector<int>& nums)
{
    int n = nums.size();
    vector<int> ans(2 * n);
    for (int i = 0; i < n; i++)
    {
        ans[i]     = nums[i];
        ans[i + n] = nums[i];
    }
    return ans;
}
```

**Approach 1:**

```cpp
vector<int> getConcatenation(vector<int>& nums)
{
    vector<int> ans(2 * nums.size());
    for (int i = 0; i < nums.size(); i++)
    {
        ans[i] = nums[i];
        ans[i + nums.size()] = nums[i];
    }
    return ans;
}
```

**Approach 2:**

```cpp
vector<int> getConcatenation(vector<int>& nums)
{
    vector<int> ans;
    for (int i = 0; i < nums.size(); i++) ans.push_back(nums[i]);
    for (int i = 0; i < nums.size(); i++) ans.push_back(nums[i]);
    return ans;
}
```

## 8. Improvements

- **Store `n` once** (approach 1 to 3): cleaner code, and it removes the signed/unsigned compiler warning from comparing `int i` with `nums.size()`.
- **Add `ans.reserve(2 * nums.size());`** to approach 2: all room is allocated once, so there are no re-allocations or extra copies. You must still use `push_back`, because `reserve` changes capacity, not size.
- **Prefer `vector` over runtime-sized arrays** like `int a[n]`, which are not standard C++.
- Big-O cannot improve. The gains are in constants, memory behavior, and readability.

**Ranking:** approach 3, then approach 1, then approach 2.

## 9. Mistakes

- **Going out of range.** C++ does not stop you. This is undefined behavior: it may pass locally and fail on the judge.
- **Mixing up `v(k)` and `v;`.** `vector<int> v(3)` already holds three zeros, so `push_back` after it adds a fourth slot after those zeros.
- **Writing `=` where you mean `==`,** or the reverse. `=` stores a value, `==` compares.
- **Returning a plain local array.** It disappears when the function ends (a dangling pointer). Return a vector instead.
- **Printing extra text.** Judges compare output exactly, so labels or extra numbers give Wrong Answer.
- **Fixing one line instead of the pattern.** If one mistake is pointed out, look for the same mistake elsewhere.
- **Running before predicting.** Guess the output first. Input `3` then `9 8 7` should print `9 8 7 9 8 7`.

## 10. Learnings

- Before writing a loop, say what **one round does** and **how many rounds** there are.
- For every loop, find the **smallest and largest index** it touches.
- **Trace a small input** by hand, then test edge cases (size 1, duplicates, maximum size).
- Complexity counts **steps, not seconds**. Explain the *reason*, not just the Big-O.
- **Space and extra space are different questions.** Say both.
- `size` is how many elements exist, while `capacity` is the room available.
- Checking finished work against the original requirements is the same skill as testing against edge cases.
